# err-template

A starting point for small offline Flutter apps for Android, set up the way
[err](https://github.com/gsilvers/err) and
[pixlerr](https://github.com/gsilvers/pixlerr) are: GitHub Actions builds a
signed APK on every push to `main` and publishes it as a release, and
[Obtainium](https://github.com/ImranR98/Obtainium) installs it on a
GrapheneOS phone. No Play Store and no Google services involved.

What you get:

- A minimal Flutter app (Android only) with a widget test.
- `.github/workflows/build.yml`: analyze, test, build a release APK, publish
  it as a GitHub release (details in [docs/releases.md](docs/releases.md)).
- Release signing from repository secrets, with an installable fallback when
  they aren't set yet.
- Debug builds that install next to the release build, as "App (debug)".
- `tool/rename.sh` to turn the template into your app in one command.
- Setup guides for building on a Mac ([docs/macos.md](docs/macos.md)) and
  on the phone itself in Termux ([docs/termux.md](docs/termux.md)).

## Starting a new app

These steps use the GitHub CLI (`gh`), which works the same on a Mac
(`brew install gh`) and in Termux (`pkg install gh`). Run `gh auth login`
once first. The examples make an app called *blerr*.

### 1. Create the repo from the template

```sh
gh repo create blerr --public --template gsilvers/err-template --clone
cd blerr
```

Or on GitHub: open this repo, click **Use this template → Create a new
repository**, then clone it.

Use the template rather than a fork: a fork stays tied to err-template and
GitHub allows only one fork of a repo per account, while a repo made from
a template is independent and starts with a fresh history.

The template's own first commit runs the build workflow once. Without
signing secrets it only builds, and publishes nothing.

### 2. Rename it

```sh
tool/rename.sh blerr "Blerr" io.github.gsilvers.blerr
```

The arguments are the Dart package name, the name shown on the phone, and
the Android application ID. Pick the ID with care: changing it after a
release makes Android treat the app as a different one, with no upgrade
over the old install. `io.github.<your GitHub name>.<app>` is a safe choice.

The script also replaces this README with a short one for your app and
updates `AGENTS.md`. Look over `git diff`, then commit and push:

```sh
git add -A
git commit -m "Rename template to blerr"
git push
```

### 3. Add a signing key

Do this once per app, before the first release. Without it CI still builds
an APK, but publishes no release. The steps are in
[docs/releases.md](docs/releases.md#setting-up-signing); they end with four
`gh secret set` commands.

### 4. Build and install

Start a build with `gh workflow run build.yml` (or push to `main`, or use
**Actions → Build APK → Run workflow**). When it finishes there's a release
called *Build N*. In Obtainium, add the app with the repo's URL,
`https://github.com/gsilvers/blerr`, and it installs the APK and picks up
each new release.

### 5. Develop

Set up Flutter on the machine you'll work on:

- [docs/macos.md](docs/macos.md): a Mac, with the Android emulator or a phone
  over USB.
- [docs/termux.md](docs/termux.md): the phone itself. Tests and debug builds
  run in Termux; release builds come from CI.

Both come down to the same commands:

```sh
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
```

## What's in the repo

```
lib/main.dart                # The app: replace the placeholder screen
test/widget_test.dart        # A widget test to start from
android/                     # Android project: app ID, label, signing
tool/rename.sh               # Step 2 above
tool/termux/                 # Phone setup and its flutter wrapper
docs/                        # macOS, Termux and release docs
AGENTS.md                    # Notes for coding agents working on the app
.github/workflows/build.yml  # CI: analyze, test, build, release
```

A license isn't included; add the one you want (err uses AGPL-3.0).

## Updating the template

The Android project was generated by `flutter create` with Flutter 3.47.
When a new Flutter release changes the generated files, regenerate them in
a scratch folder with
`flutter create --org io.github.gsilvers --project-name err_template --platforms android`
and copy over what changed, keeping the signing and label sections in
`android/app/build.gradle.kts`.
